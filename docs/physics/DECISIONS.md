# Reactive physics decisions

These decisions express the user's requested priorities and the implementation plan. Change one when concrete integration evidence warrants it; include the date, reason, affected contracts and migration consequence. Do not present planned behavior as implemented.

| ID | Decision | Reason |
| --- | --- | --- |
| D01 | Physical interaction breadth and visible results take priority; performance measurements are informational | User explicitly owns performance tradeoffs |
| D02 | Official Rapier2D JavaScript/WASM package behind a local adapter; no initial fork | Delivers collision/joint capabilities while keeping Fern's gameplay inspectable |
| D03 | One authoritative physical owner per body; host simulates shared worlds | Avoids competing integrators and divergent guest worlds |
| D04 | One fixed tick pipeline; zero global gravity; explicit unit conversion | Fits the current top-down game and existing stepping tools |
| D05 | Optional features resolve by land, area and region; runtime overrides have explicit precedence | User requires controllable physics in selected parts of the world |
| D06 | Off preserves current consequences; re-enable never resurrects objects or rewards | Switches must work in a live run |
| D07 | Physics snapshots plus semantic state and stable game IDs | Saves, inspection, migrations and co-op need more than raw engine handles |
| D08 | Same-build reproducibility is useful; cross-device bit identity and scientific precision are not gates | User favors reactions and does not require hardware parity |
| D09 | Existing combat/progression stays gameplay-owned; reactions add physical consequences | Maintains fast attacks, optional mechanics and correct rewards |
| D10 | Cosmetic-only particles do not satisfy destruction, ragdoll or interactive-object milestones | Acceptance must demonstrate actual world state changes |
| D11 | Each milestone is a complete verified slice, pushed and merged before a fresh session | User explicitly requests milestone resets and commit discipline |
| D12 | No claim of self-switching models, self-clearing context or reserving 828K tokens | Those are controlled by the active client; repository handoffs provide continuity |
| D13 | Scenery and creature interaction remains an explicit authored/user choice, without hidden FPS-driven caps | Honors broad physics options without making population benchmarks dictate scope |

| D29 | M04 release audit moves transport to room 5 / physical wire 2 with lossless native gzip, bounded inflation, paced chunk bursts and immutable retries | Initial PR #6 checks passed, but main/production high-population verification exposed false inactivity and late-join starvation. Connected native channels were losing completion while new retry manifests superseded staged scenes. Retry the identical scene, acknowledge committed duplicates, invalidate caches after accepted actions, refresh liveness on valid traffic, and keep every selected body. An eight-second native payload delay verifies first-attempt atomic loading. See the [Compression Standard](https://compression.spec.whatwg.org/). |
| D30 | Complete frames use one shared, cost-spaced build with admission/acknowledgement floors, staged receipts, 256 KiB paced refills (1 MiB starved admission) and a 1 Hz host heartbeat | PR #7's repair still failed CI on both commits. At 32,768 creatures a loaded host processed guest acknowledgements 3–10 s late, so stop-and-wait guests heard nothing for 10 s and continued solo. Per-hello population-sized `begin()` rebinding and per-guest builds amplified host load, blind five-second resends doubled work for guests still decoding, and four chunks per rendered frame capped transfer. Liveness now follows a host heartbeat; frame cadence (never participation or eligibility) follows measured build cost. Room 5 / wire 2 framing is unchanged; older peers ignore the new messages. |
| D31 | Ambient ownership bookkeeping memoizes policy resolution per immutable policy state and caches area footprints; results are frozen and samples are updated in place | M03's per-tick, per-creature pass rebuilt area recipes and policy objects for every creature, 70% of a 32,768-creature tick. Medians fell from 38/184/436 ms to 18/78/177 ms at 6,000/32,768/65,536 creatures. |
| D32 | M05 durability is a percentage; families own toughness/reward/pieces, materials own resistance/vulnerability/response; `materialDurability` divides material damage | One readable number survives saves and inspection. | D35 | Debris lifetime is sampled from the break site's policy into an absolute `expiresAt` tick; expiry runs at the begin boundary in sorted ID order; 0 means scene lifetime | Deterministic cleanup survives save/replay without a hidden timer and never depends on FPS. | D37 | Attacks, not contacts, damage scenery in M05; Thornlance projectiles ignore scenery | M06 owns impact damage and projectile world collision with their own policies. Keeping M05 damage on authored hits makes repeated-contact rewards impossible by construction. 2026-10-05. |
| D38 | Per-tick and per-observation physics reads never deep-clone: finite checks read Rapier directly; poses and saves copy recipes, policies, entries and ambient samples structurally; `stateHash` covers raw Rapier bytes through the snapshot checksum; only movable props occupy terrain chunks | A pre-existing per-tick `poses()` validation cloned every body twice, and every `observe()` hashed a full save with its byte array serialized as JSON. Final M05 combat ticks match main's despite 2.5× the bodies, and `observe()` costs less than on main ([evidence](../evidence/physics-m05-tick.json)). | D39 | One attack interaction spec (`ATTACKS`) drives every damaging action's physical side; gameplay keeps authored damage and rewards | Abilities, mechanics, charges, shots and impacts stay comparable and inspectable; a new mechanism adds a recipe instead of bespoke physics. 2026-10-05. |
| D40 | Launched props carry a 2.5 s instigator; started contacts become pending impacts applied at the next tick boundary through the ordinary hit path | Damage and rewards happen outside Rapier's contact iteration, survive saves and replays, and are granted exactly once with the right credit. | D41 | Thornlance pierces fragile scenery free, spends a pierce on wood and stops (or ricochets) on stone, metal, stumps and rooted terrain; enemy shots treat scenery as cover; water is never cover | Gives cover and line of fire meaning without disabling base hits when projectile-world collision is off. 2026-10-05. |

| D45 | Assemblies and joints live in `PhysicsWorld` beside bodies; members name their assembly; each connected part resolves policy once at its root (declared anchor, or the first listed member of a part cut loose) and checkpoints enforce it | A region boundary can never split a chain; freezing and waking act on whole parts; joints keep the single owner of Rapier handles. 2026-10-05. |
| D46 | Joint strain = momentum of the connected part moving away from the joint's anchor before each solve (ropes when taut, springs past 2.5× rest, sliders across their axis); break when load > breakLoad × jointStrength | Rapier 0.21 has no joint force readback; anchor error was erratic (0.26 → 11.6 units between similar blows) and zero under velocity-driven holds, while momentum captures yanks, throws, holds and pushes and ignores free swinging. 2026-10-05. |
| D47 | Joints are created without wake-up or any Rapier joint setter; limits and motors are Fern pre-solve velocity rules; authored gaps replace disabled contacts | Setter wake-ups sit in a hash set whose order changes across a snapshot restore until the next step, so unstepped checkpoints did not round-trip byte for byte (replays diverged); a zero-length flush step later panicked Rapier's islands. 2026-10-05. |
| D48 | A post-solve projection walks each part from its root and restores hinge pins and rope lengths | Under a sustained pull an eight-body vine stretched to 180/70 units at 4 solver iterations and 120/70 at 16; the projection keeps tethers exact (70.0/70) without raising global iterations. 2026-10-05. |
| D49 | Mechanism parts are never destroyed; attacks cut the nearest joint by material damage instead | Removing a member would silently drop its joints and orphan the assembly; cutting gives the same player verb (strike to free) with an explicit, saved break. 2026-10-05. |
| D50 | Six mechanisms per area in the north meadow and west edge, off required travel; every area gains a wadeable creek that the causeway spans (anchored planks cancel wading); waves never start inside a gate pen | Mechanisms must be optional shortcuts, never blockers: a jammed gate or cut causeway costs time or a cache, not progress. Shallow water has no physics body, so older terrain checkpoints stay valid. 2026-10-05. |
| D51 | Gate latch, launcher fire and causeway span are authored mechanism events; chain, vine and vane move only physically | Distinguishes gameplay state (a latched motor, an owned launch, deck travel) from free physical response, as the card requires. 2026-10-05. |
| D52 | Physical world 7, adventure envelope 5, room protocol 8; M06 checkpoints gain mechanisms once, archived lands on return | Assemblies, joints and mechanism state are saved and replicated in the complete scene; content that never existed is added fresh, never rebuilt over existing state. 2026-10-05. |
