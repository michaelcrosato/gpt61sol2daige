# M02 Regional controls and live transitions

Dependency: M01 verified and merged. Read all of `POLICIES.md`. Deliver working feature control by land, area and named region, including live changes and clear inheritance.

## Steps

1. Implement validated policy/profile/region schemas, stable scope IDs, priority resolution, boundary membership and revisioned commands. Add authored area/land defaults without yet claiming later feature systems exist.
2. Make master world reactions, dynamic props and prop blocking affect the playground's real bodies. Add region shapes and membership inspection. Other controls register only when their systems arrive.
3. Add physics controls to pause/debug UI: selected scope, effective values, provenance, override/reset and presets. Include a body selector and region overlay. Extend `describe` and the scene runner with configure and inspect operations.
4. Implement queued atomic on/off changes, frozen current poses, zero-velocity reactivation, overlap correction and reset-this-scope. Preserve destroyed/claimed state fields in the schema rather than rebuilding the scene on every edit.
5. Add basic policy serialization and browser preference separation. Shared behavior belongs to world state; overlays may remain device-local. Shared controls are unavailable to guests until M04 provides the authorized transport.

## Acceptance

- The same crate responds in a reactive region, freezes in a quiet region and responds again after returning or re-enabling; it does not jump back to spawn.
- Broader and more specific overrides resolve as documented, including absolute master-off. Invalid/stale commands leave state unchanged.
- Editing a region while paused gives an inspectable result. A saved/reloaded playground retains profiles, regions and overrides.
- Unimplemented capabilities are not presented as working toggles. UI and agent commands produce the same result.
