# M12 Complete controls showcase and release

Dependency: M11 verified and merged. Finish the full reactive-world experience and verify its behavior as one product.

## Steps

1. Complete pause/debug physics controls, preset explanations, selected-region editing, per-object inspection and reset behavior. Give keyboard, mouse and touch users discoverable access. Keep implementation internals in the lab/debug surface.
2. Make Reactive the normal adventure profile, Sanctuary the town profile and all available controls honest. Remove obsolete rollout switches or clearly retain only intentional developer comparison tools.
3. Assemble a reusable showcase route containing destructible scenery, a launched prop kill, a jointed mechanism, a material chain, a physical rig death and a regional off/on transition. Provide a scene recipe and a readable short demonstration capture.
4. Run the full functional matrix: authored outward run, generated continuation, controls disabled, save during an active reaction, legacy save migration, scoped overrides, same-build replay/debugging, and a co-op smoke check over actual WebRTC (join, late join and disconnect) at the party size the game then supports.
5. Update README, architecture, agent protocol, verification and hosted documentation. Explain new controls and how to reproduce the showcase. Record unresolved limitations precisely; do not label a missing planned system complete.
6. Push/merge the release, verify the production commit and site, then run the relevant live browser scenarios. Confirm the working tree and remote agree.

## Acceptance

- Every feature in `POLICIES.md` has a real on/off demonstration and the relevant boundary/save/guest checks. Dependency combinations have been tested without demanding an exhaustive boolean permutation suite.
- All twelve milestone experiences are reachable in the game or deliberate tools, with no remaining placeholder control or disconnected final feature.
- The normal play loop remains responsive in its controls and legible in its effects. Report any observed slowdown to the user as information; do not make an FPS threshold or cross-hardware precision guarantee the release gate.
- All required checks pass, production is verified, and the final report distinguishes implemented systems, tuning choices and genuine remaining gaps.
