# M05 Materials and destructible scenery

Dependency: M04 verified and merged. Deliver scenery whose material determines how it moves, breaks and remains changed.

## Steps

1. Add a material registry for wood, stone, metal, glass, cloth, vegetation, ceramic and volatile containers. Define response and durability in shared recipes, with visible/sound identity.
2. Build prop blueprints covering crates, barrels, pots, logs, loose stones, wheels, wagons, fences, glass pylons, lanterns and trees. Add coherent variations for the five land palettes; do not treat recoloring a single box as the full prop family.
3. Implement damage stages and seeded/authored fracture pieces with inherited motion, colliders and persistent destroyed-parent IDs. Convert a broken tree into a stump and fallen physical timber with matching visuals.
4. Connect basic attack/impact hooks to material damage and one-time destruction rewards. M06 expands offensive physical interactions; this milestone must already let a player visibly break scenery.
5. Add foliage/cloth response hooks, material-specific sound and dust/splinter/glass feedback. Declare which fragments are gameplay solids and which are presentation-only.
6. Extend region policies, save/restore, network spawn/destroy delivery and agent inspection for the new state. Preserve alterations on recall/re-entry; debris cleanup follows an explicit configurable lifetime or scene lifecycle.

## Acceptance

- A crate splinters, a glass pylon shatters, stone resists a weak hit, and a tree leaves a stump plus a log that can be pushed.
- Disabling destruction preserves existing damage and prevents new breakage; disabling dynamics freezes pieces without reconstructing the parent.
- Continuous contact does not destroy/reward an object repeatedly. Save/load, recall and late join preserve the same meaningful destruction state.
- Each prop family has a readable silhouette and material response in the actual game and a reproducible recipe export.

## Handoff

Record material/blueprint schemas, persistent mutation keys, fracture ownership and reward rules. Push/merge; write `handoffs/M05.md` and reset before M06.
